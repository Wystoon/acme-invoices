# AB#4840 · Invoice total off by 0.01 for some line combinations
Bug · Active · Dana Novak · tags: invoices, rounding

## Acceptance criteria
1. The invoice total is the sum of the rounded line totals: round each line first (Money.Round), then sum.
2. INV-2026-0017 shows a total of 2.02.
3. Single-line rounding does not change (2 decimals, MidpointRounding.AwayFromZero).
4. A unit test covers two lines of 3 × 0.335 (expected total 2.02); all existing tests stay green.

## Description
Repro steps
1. Run the API locally: dotnet run --project src/backend/Acme.Invoices.Api --launch-profile http
2. Open GET /api/invoices/17 (INV-2026-0017, Bluefen Bakery, EUR).
3. The invoice has two lines: "SMS credits, EU" 3 × 0.335 = 1.01 and "SMS credits, UK" 3 × 0.335 = 1.01.
Expected: invoice total 2.02, the sum of the line totals printed on the invoice.
Actual: invoice total 2.01.

Cause (Dana): Invoice.Total rounds the sum of the unrounded line amounts (1.005 + 1.005 = 2.010 → 2.01) instead of adding the rounded line totals (1.01 + 1.01 = 2.02).
